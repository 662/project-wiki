# 校验契约

校验需求与实现语言分开。复用项目已有文档工具；需要新增时按其工具链选择，例如 Go 项目可复用已有 Markdown 工具或实现 Go 校验。不要把 Node/Next.js/Python 当核心技能前置条件。

## 内容检查

- 首页及对外入口可找到；不要求固定栏目或页数。
- 元数据按本项目实际 schema 检查；稳定 ID 唯一，关联 ID 指向存在主题。
- 路径映射唯一；`a.md` 与 `a/index.md` 同时映射 `a` 时应报冲突。
- 别名与规范 ID/slug 全局不冲突；目标章节真实存在。
- 相对链接不越出内容根；内部页面及片段锚点存在。
- 参考式链接、自动链接与标题中的行内标记按实际 Markdown 语义解析；代码示例里的链接不应误报。
- 锚点算法与实际阅读器/网页渲染保持一致，重复标题正确编号。
- 禁止通过内容路径、编码、反斜杠或符号链接越过根目录读取；不能把文档中的脚本协议变成可执行链接。

自动检查采用 AST 等与实际渲染一致的解析方式；不要用一个正则宣称支持全部 Markdown。无法自动覆盖的检查说明范围并人工核验。人工检查不能冒充已接入 CI。

## 网页与图表

网页加载与校验共用路径、锚点和别名解析。先鉴权再读取/返回受限知识，包括旧地址跳转、缓存、图片和下载；不把受限资源移到 public 绕过授权。测试真实的未登录/无权/允许角色、直达和未知路径边界。

图表启用时，校验图源与配置对应资源是否存在、摘要是否匹配。生成命令有外部工具前置条件，而正式构建只读取已提交资源，不要求 Chrome 或客户端 Mermaid。

## 交付分级

内容变更检查事实、引用和 diff。解析、鉴权、路由、打包变更运行对应类型/构建和核心边界检查，做必要人工阅读。沿用项目测试策略，不强制新增 UI 自动化。

Next.js 参考资产的 `validateWiki` 是可选 Node 实现，可测试 Markdown、别名与路径边界；它不要求固定栏目。其依赖清单和调用方式见 Next.js 接入说明。资产没有通用本地图片发布器，嵌入图片需调用方增加受控解析后再启用；不要通过放宽链接边界来绕过这一限制。
