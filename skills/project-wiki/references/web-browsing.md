# 可选网页浏览

先明确网页是否需要、采用何种已有 Web 栈，以及知识的公开范围。建立 Markdown 知识不意味着获准公开或部署。没有 server 的工具可保持仓库阅读；独立静态文档站只有在用户需要时再评估。

## 共享机制

内容是同一份 Markdown；读取、目录、链接、别名和校验共享一套契约。网页不是另一份产品知识，不在线写源码文件。Markdown 不执行任意 HTML/脚本，不把未知协议直接放入 href，不因动态 slug 直接拼接文件读取路径。

只读布局与业务布局分开：阅读不要隐式打开业务 SSE、订阅、聊天状态或任务。沿用项目主题、组件和样式隔离策略，不强制 shadcn/Tailwind 或某个品牌布局。

按用户选择采用公开或受限模式。受限知识在鉴权成功后才读取并返回；页面、旧地址、下载与静态资源策略保持一致。认证回跳只扩展明确的 Wiki 路径范围，不放宽为任意站内或外部地址；已有认证机制不因 Wiki 重写。

## Express 等适配

在现有路由注册精确 Wiki 前缀；通过认证中间件/现有权限函数授权，然后从固定内容根构建索引。请求 slug 查询已验证索引，禁止 `readFile(req.params.path)` 这类直接文件映射。规范页与别名共享解析，别名跳到规范页/章节。

使用现有模板/前端渲染 AST 或安全 Markdown HTML；若输出 HTML，禁用原始 HTML或采用成熟 sanitizer，不手写转义替代完整净化。导航、目录和响应遵循现有服务模式。缓存可共享不含用户信息的内容索引，但每次请求仍按项目策略授权，不能缓存授权成功跨用户复用。

部署复制内容目录和已生成的受控资源，设置正确运行根路径；已有静态站/模板更合适时复用它。框架不同无需迁移成 Next.js，Node 资产也不自动成为所有框架的依赖。

## 验收

直达、刷新、相对链接、中文锚点、别名、窄屏和代码/表格可读；未知路径有明确结果。访问边界符合选定策略，镜像/构建产物带有所需内容。在线编辑和发布后台不在只读浏览范围内。
